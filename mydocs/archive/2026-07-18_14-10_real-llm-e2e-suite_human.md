## 1. 目标与范围

用真实 LLM（DeepSeek v4-flash）+ 真实沙箱对 Hermes Agent 做首次真实端到端联调：补齐 7/15 存疑记录（当时沙箱未真实执行），验证技术债治理成果在真实环境的表现，并沉淀可重复执行的场景套件。

## 2. 关键决策

1. **场景套件而非手动单次**：`e2e_suite.py` 自动提取轮数/工具序列/耗时/证据断言，输出可粘贴进 evaluation-log 的报告——联调从一次性动作变成可回归资产。
2. **证据断言标准**：不看"跑完了"，看 trace 里真实发生的工具调用 + 沙箱输出中的预期值（Done by Evidence）。
3. **S3 双场景设计**：禁网原样跑（S3）+ 预置镜像对照（S3b）——把"安全 vs 自愈"的张力变成可测量数据。
4. **失败如实记录**：S2/S4 FAIL 不掩饰、重跑确认非抖动、定性为模型行为偏差。

## 3. 结果与证据（7 场景，约 30 轮真实 LLM 调用）

| 场景 | 结果 | 关键数据 |
|---|---|---|
| S1 fibonacci 复跑 | ✅ | 3 轮 8.2s，真实沙箱验证 55，覆盖 7/15 存疑记录 |
| S2 文件工作流 | ❌ | LLM 用 sandbox_exec 通吃，跳过 file_write/file_read（重跑稳定） |
| S3 numpy 自愈（禁网） | ✅ | 5 轮 23.1s，禁网下降级完成 |
| S4 多工具链+编辑 | ❌ | 稳定跳过 file_edit（重跑确认） |
| S5 策略拦截 | ✅ | TD-006 边界真实生效，Agent 被拒后换方案 |
| S1-sub 对照 | ✅ | subprocess 后端等价性验证通过 |
| S3b 预置镜像对照 | ✅ | 比 S3 快 63%（8.5s vs 23.1s） |

## 4. 两大发现

1. **LLM 工具偏好**：DeepSeek 倾向用 sandbox_exec 通吃，稳定跳过专用文件工具——不是产品缺陷，是模型行为与工具引导的错位，转化为后续优化项（system prompt / 工具描述 / few-shot）。
2. **禁网自愈边界实测**：pip 不可用时 Agent 能降级完成；预置镜像（模式 1）是同任务快 63% 的更优解——为 TD-010（两阶段网络）提供实测依据。
