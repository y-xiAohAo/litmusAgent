## 1. 目标与范围

为写/编辑类工具提供可选的人工确认钩子：启用后 `file_write` / `file_edit` 执行前须用户批准，拒绝则返回失败。本单元交付核心机制 + CLI 交互；**Web UI 确认明确排除**（per-call 确认需挂起/恢复机制，属详规 Non-Goal，留待后续单元）。

## 2. 关键决策

1. **仅 CLI**（用户拍板）：Web 请求-响应模型与 per-call 确认存在架构冲突，不为小功能引入异步等待工作流。
2. **y/n/a 三选语义**（用户拍板）：y=本次允许、n=拒绝、a=本会话该工具免确认（按工具名隔离，不泄漏）。
3. **复用 TD-004 注入模式**：`Agent(approval_callback=...)` → `ToolRegistry` 统一入口，策略检查后、执行前确认——机制已被上轮验证。
4. **拒绝文案显式化**："用户拒绝了操作，这不是系统错误，不要盲目重试"——防止 LLM 误分类为系统故障而重试死循环。
5. **策略优先于确认**（评审实证）：被 PolicyEngine 拦截的操作不触发人工确认——不该问用户的事不问。

## 4. 风险与遗留

1. Web 会话无确认能力（待独立单元）。
2. 真实终端交互未自动化（建议真实 LLM 联调时手测）。
3. `a` 免确认仅会话级，无跨会话持久化（新需求候选）。

## 5. 汇报口径（可直接引用）

> 为 Hermes Agent 的写操作增加可选人工确认机制：复用注册表统一入口注入确认 callback，CLI 提供 y/n/a 三选交互（支持会话级免确认），拒绝结果显式标注防止 LLM 误重试；策略引擎拒绝优先于人工确认。新增 11 个测试，全量 615 passed，未启用时行为零变化。
