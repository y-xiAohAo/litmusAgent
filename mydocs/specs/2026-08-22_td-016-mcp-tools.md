# Feature Spec — TD-016：MCP 工具接入

## 1. 目标

让 Agent 的工具注册中心支持接入 MCP（Model Context Protocol）server 提供的工具：配置声明 server → 连接并发现工具 → 包装为 ToolSpec 注册 → 走统一卡口（策略/审批/Trace/外迁）。

## 2. 风险与规范性改变评估（核心章节，评审重点）

### 2.1 与现有架构的关系（好消息）

| 现有机制 | MCP 接入后的表现 |
|---|---|
| ToolRegistry（ToolSpec + async handler 字典注册） | 零协议改动，MCP 工具包一层即注册 |
| `_PARAMETRIC_CHECKS` / PolicyEngine | 自动生效，但需补"动态工具名"的策略口径（§2.3-R2） |
| 人工确认钩子（TD-008） | 自动生效，可把 MCP 工具加入确认清单 |
| Trace / 结果外迁 / 错误前缀约定 | 自动生效，需做 MCP 错误 → `{ExcName}: ...` 映射 |
| `Agent.close()` 生命周期收口（TD-015 单元 B） | 现成挂点，MCP server 子进程在此回收 |

### 2.2 规范性改变（要动约定的地方）

- **C1 新增可选依赖**：`mcp` 包走 optional extra（`pip install agent[mcp]`），照 `openai`/`anthropic` 先例，不进核心依赖——未安装时配置 `mcp:` 段报友好错误。
- **C2 新增顶级配置块** `mcp:`：现有配置块（llm/agent/sandbox/tools/security/memory）的同级别新增，YAML 风格对齐。
- **C3 工具注册时机变化（最大范式触碰）**：现有工具全部在 `Agent.__init__` 同步注册；MCP 工具需要**异步**连接 server 后才能发现。这引入"异步装配"新时机——候选方案见 §3。
- **C4 宿主执行边界**：MCP server 是**宿主机进程**，其工具在宿主执行、不经沙箱——与"LLM 代码只在沙箱跑"的既有哲学正面碰撞，安全默认必须保守（§2.3-R1）。

### 2.3 风险清单

- **R1 🔴 供应链 / 宿主执行**：第三方 MCP server = 在用户机器上以用户权限跑任意代码（等价于 `pip install` 的信任级别）。缓解：配置即信任声明（文档醒目）；MCP 工具**默认 deny**（需显式白名单）；建议默认进人工确认清单。
- **R2 🟠 动态工具名的策略缺口**：`_PARAMETRIC_CHECKS` 是静态表，MCP 工具名运行时才知道。口径设计：MCP 工具统一映射通用 subject（如 `mcp/<server>/<tool>`），提供默认策略规则锚点；细粒度规则用户可在 YAML 里按名字写。
- **R3 🟠 会话僵死**：server 挂起时 `call_tool` 可能不返回（MCP SDK 已知问题：cancel 通知不保证 server 收，[python-sdk#2507](https://github.com/modelcontextprotocol/python-sdk/issues/2507)）。缓解：`asyncio.wait_for` 外层强制超时（EVAL-009 同款先例），超时后标记 server 降级。
- **R4 🟡 事件循环绑定**：stdio client 绑创建时的事件循环；CLI chat 已复用单一循环（EVAL-012 修复），Web 端多 session 各起各的 server——装配点要与现有循环管理对齐。
- **R5 🟡 Windows 兼容**：`npx`/`uvx` 类 server 启动命令在 Windows 需 shell 语义（`cmd /c`）；文档注明 + 实测。
- **R6 🟡 命名冲突**：不同 server 可能暴露同名工具 → 强制前缀 `mcp__<server>__<tool>`（Claude Code 先例）。

### 2.4 SDK 事实（已核实）

- 官方包 `mcp`（pip install mcp）：`from mcp import ClientSession, StdioServerParameters`、`from mcp.client.stdio import stdio_client`；`AsyncExitStack` 管理多层连接；`session.initialize()` → `session.list_tools()` → `session.call_tool(name, arguments)`。
- stdio 与 SSE/HTTP 传输 SDK 均有内置支持。

## 3. 设计草案（待澄清项见 §6）

### 3.1 配置（裁决：三种传输都要；server 级 trust 开关）

```yaml
mcp:
  tool_timeout: 30        # 单次 MCP 调用超时（秒），wait_for 强制
  servers:
    - name: filesystem           # stdio 形态：command + args
      command: npx
      args: ["-y", "@modelcontextprotocol/server-filesystem", "/tmp"]
      # env: {...} 可选
      trust: false               # true = 该 server 工具免人工确认（默认 false，全确认）
    - name: remote-search        # SSE/HTTP 形态：url + 可选 headers
      url: http://localhost:8000/sse
      # headers: {Authorization: "Bearer ..."}  可选
      trust: false
```

校验：同一 server 的 `command` 与 `url` 互斥且必居其一；`name` 匹配 `^[a-zA-Z0-9_-]+$`（要进工具名前缀）。

### 3.2 装配与注册（裁决：惰性连接）

- `Agent` 首次 `run()` 前惰性连接（内部 `_ensure_mcp_connected()`，只在配置了 `mcp.servers` 时激活；连接失败单 server 跳过 + warning，全部失败也不阻塞 Agent——裁决：跳过降级）。
- `MCPManager`（新模块 `src/agent/mcp_client.py`）持有 `AsyncExitStack`，每 server 一个 `ClientSession`（stdio 或 SSE/HTTP 按配置形态）。
- 发现的工具包装为 ToolSpec：`name=f"mcp__{server}__{tool}"`；handler 内 `session.call_tool` + `asyncio.wait_for(tool_timeout)`（R3 僵死防护）+ 错误映射（MCP isError → `ToolResult(success=False)`，内容带 `MCPError:` 前缀）。
- 注册进 ToolRegistry 默认层 → 策略/审批/Trace/外迁自动生效；受 `tools.enabled` 白名单控制（全名匹配）。

### 3.3 安全默认（裁决：默认全确认）

- MCP 工具默认全部进人工确认清单；`trust: true` 的 server 豁免。
- 策略层：MCP 工具统一映射 subject `mcp/<server>`（operation `call`），用户可在 YAML 里按此写自定义规则；默认规则集不加 MCP 条目（确认钩子是主防线）。

### 3.4 生命周期

`Agent.close()` 追加 `MCPManager.close()`（`AsyncExitStack.aclose`），复用 TD-015 单元 B 收口链路；web shutdown 路径自动继承。

## 4. 范围

**In**：三种传输（stdio + SSE/HTTP，裁决）；配置块（command/url 互斥校验、tool_timeout、trust）；MCPManager + 惰性装配；ToolSpec 包装（超时/错误映射/前缀命名）；安全默认（默认全确认 + mcp/<server> subject）；close 收口；测试（fake server 用 SDK FastMCP 起进程内 server，stdio 真实链路 + SSE/HTTP 本地起服务实测）；文档。

**Out**：MCP resources/prompts（只接 tools）；server 自动发现/市场；远程 server 的 OAuth 流程（headers 静态配置已够首版）；流式进度通知。

## 5. 验收

- fake MCP server（FastMCP，两工具）：stdio 与本地 SSE 两种形态下 Agent 均能列出并调用，结果正确回传。
- 未装 `mcp` 包 + 配置 mcp 段 → 友好报错（ImportError 转中文提示）。
- MCP 工具默认触发人工确认；`trust: true` 豁免；策略 deny 生效。
- server 僵死 → `tool_timeout` 超时返回失败结果（`MCPError:` 前缀），Agent 继续。
- 单 server 连接失败 → 跳过 + warning，其余可用；全部失败不阻塞 Agent。
- `agent.close()` 后 server 子进程退出（psutil 或轮询验证）。
- 门禁全绿（基线 901）。
