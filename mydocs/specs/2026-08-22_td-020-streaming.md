> **前置调研**：影响面评估（候选 A/B、57 处 mock 兼容性、OpenAI SSE 协议）+ DeepSeek V4 协议核查（2026-08-22）

## 1. 目标与范围

让 Agent 的"黑箱等待"变为可观测过程：最终回复逐字流式、思考链（reasoning）可见、工具调用进度实时渲染。同时完成 DeepSeek V4 协议适配。

**In**：
1. `BaseLLMClient.chat_stream()`（方案 A：带默认回退实现，57 处现有 mock 零改动）
2. OpenAIClient SSE 解析 + tool_calls 分片聚合 + `reasoning_content` 分片捕获
3. 引擎 `on_token` 旁路（主循环，含 FATAL 解释轮）
4. CLI 三层渲染：content 流式（Rich Live / plain 直出）、思考链折叠渲染、工具调用进度行
5. DeepSeek V4 适配：`thinking` 开关配置、`reasoning_content` 解析与**多轮回传规则**、文档/示例中的退役模型名清理
6. 配置：`llm.stream: bool = False`（默认关，零回归）、`llm.thinking: bool = False`

**Out**：Web 端流式（SSE 端点 + 前端，并入 TD-022 一起做）；Pi 式"流进内循环"重构（已论证不做，见调研记录）；Anthropic 协议适配。

## 2. 调研结论摘要（决策依据）

- **方案 A**（`chat_stream` 默认实现回退非流式）：57 处测试 mock 零改动，引擎只动一行调用点。方案 B（纯 AsyncIterator）被否。
- **消费方**：仅引擎主循环（用户可见回复）需要流式；Planner/记忆/摘要/评测全部无感。
- **DeepSeek 协议**（2026-08-22 核查）：`deepseek-chat`/`deepseek-reasoner` 已于 2026-07-24 退役；现役 `deepseek-v4-flash`/`deepseek-v4-pro`，思考模式由请求参数控制，`reasoning_content` 与 `content` 同级返回；**多轮对话中 reasoning_content 的回传规则需实测确认**（有 400 报错先例，AstrBot#7826）——这是本单元最大的实测风险点。
- **usage 口径**：`stream=True` 默认不返回 usage，需 `stream_options={"include_usage": true}`；不支持的端点降级本地估算。

## 3. 设计

### 3.1 客户端层

```python
# llm/base.py
TokenCallback = Callable[[str], None]

@dataclass
class StreamEvents:
    on_token: TokenCallback | None = None        # content 分片
    on_reasoning: TokenCallback | None = None    # reasoning_content 分片

class BaseLLMClient:
    async def chat_stream(self, messages, tools=None, *, events=None, **kwargs) -> dict:
        """默认实现：回退 chat()，收完一次性回调。"""
```

- 返回 dict 结构**不变**（`content`/`tool_calls`），新增可选 `reasoning_content` 键（引擎透传进 Message，多轮时按端点规则回传——DeepSeek 实测后定）。
- `OpenAIClient.chat_stream`：`client.stream("POST", ...)` + `aiter_lines` SSE 解析；tool_calls 按 index 聚合（首片带 id/name，arguments 字符串拼接；坏分片跳过 + warning）；`include_usage: true`；**重试策略：仅在产出任何 token 前允许重试**（已渲染的 token 不可收回）。
- `EchoClient.chat_stream`：逐词吐出 echo（模拟流式，供测试与演示）。

### 3.2 引擎层

- `Agent.__init__` 新增可选 `stream_events: StreamEvents | None`（照 ApprovalCallback 先例）。
- 主循环 LLM 调用点：`config.llm.stream` 开启且 `stream_events` 存在 → `chat_stream`，否则 `chat()`。聚合后逻辑零改动。
- 工具执行进度：主循环在工具执行前后经 `stream_events` 发 `on_tool_start(name, args_summary)` / `on_tool_end(name, ok)`（StreamEvents 扩展两个可选回调）。

### 3.3 CLI 渲染层

- `chat.py`/`agent_cli.py`：stream 开启时构造 StreamEvents 注入 Agent。
- content：Rich `Live` 增量渲染 Markdown（plain 模式 `print(end="")`）。
- 思考链：灰色/斜体折叠区块（默认收起，结束后可展开查看；plain 模式前缀 `[thinking]` 直出）。
- 工具进度行：`→ file_write /workspace/main.py` + 结束时 ✓/✗。
- `run()` 返回值与现有结构不变（最终文本不变）。

### 3.4 DeepSeek V4 适配

- `LLMConfig` 加 `thinking: bool = False`；开启时请求体带 `thinking: {"type": "enabled"}`（OpenAI 兼容通道以 `extra_body` 等价形式）。
- 响应解析捕获 `reasoning_content`（非流式与流式都要）。
- **多轮回传规则实测**：用真实端点验证"assistant 消息是否必须携带 reasoning_content 回传"，按实测结果实现（回传或剥离），结果回写本节。
- 全仓清理退役模型名引用（examples/config.yaml、docs 等处的 `deepseek-chat` → `deepseek-v4-flash` 口径注释）。

**实测记录（2026-08-22，实施期）**：实施环境无 `OPENAI_API_KEY`/`OPENAI_BASE_URL`，**reasoning_content 多轮回传规则待真实端点补验**。当前实现按 DeepSeek 官方文档口径：多轮对话不回传 reasoning_content（官方明确回传与否不影响输出，且有回传触发 400 的先例 AstrBot#7826，故选择不回传更安全）——引擎不把它写入 Message 历史，仅用于渲染层展示。补验方式：真实端点第一轮 thinking 请求拿 reasoning_content，第二轮分别回传/不回传对比是否 400，结论回写本节。

**实测记录（2026-08-22，真实端点 deepseek-v4-flash 补验）**：
1. **thinking + stream 正常**：思考模式流式请求收到 164 个 reasoning_content 分片 + 6 个 content 分片，聚合与回调均正常。
2. **reasoning_content 多轮回传规则**：回传与不回传 assistant 消息的 reasoning_content 均不触发 400——当前"不回传"实现安全，维持不变。
3. **usage bug 与修复**：流式中间 chunk 带 `"usage": null`，仅末帧携带完整 usage 对象；`_do_chat_stream_request` 已改为"仅当 chunk usage 非 null 时更新，取最后一个非 null 值，流结束后一次性累加进 usage_totals"（`src/agent/llm/client.py`），回归测试 `test_usage_null_middle_chunk_last_non_null_wins` 覆盖。

## 4. 验收

- EchoClient 流式：CLI `--echo` 下可见逐字输出。
- 真实 DeepSeek v4-flash 端点：stream 开启 → 逐字渲染 + usage 计数与非流式口径一致（允许 ±5% 估算差）。
- thinking 开启（v4-flash 思考模式）：思考链折叠渲染、多轮对话不 400（回传规则实测记录）。
- tool_calls 分片聚合：构造乱序/截断分片的单测 + 真实工具调用流式下正常执行。
- 流式中途断连：已渲染内容保留 + 错误尾部呈现，不重试；Trace 标注 partial。
- 默认 `stream: false` 零回归：全量门禁绿（基线 934）。

## 5. 风险
