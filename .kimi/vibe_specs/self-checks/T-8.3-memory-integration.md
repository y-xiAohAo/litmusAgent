# 自检报告：Task 8.3 — 主循环集成 + `memory_read` 工具

## 1. 任务目标

把 Phase 8.1/8.2 实现的存储层、提取层、管理层接入 `Agent` 主循环：

- `Agent.__init__` 根据 `MemoryConfig.enabled` 自动创建 `MemoryManager`。
- `Agent.run()` 启动时注入历史记忆到 system prompt。
- `Agent.run()` 结束时提取记忆并记录 `memory_recorded` Trace 事件。
- 新增内部工具 `memory_read(uri)`。
- 新增集成测试验证端到端链路。

## 3. 实现要点

### 3.1 `MemoryManager.read(uri)`

- 支持 URI 格式 `hermes://memory/<category>/<entry_id>.jsonl`。
- 解析 category、entry_id，调用 `store.get(entry_id)`。
- 返回完整 entry JSON（含 metadata）；失败/非法返回 `None`。

### 3.2 `memory_read` 工具

- 内部工具，不受 `config.tools.enabled` 控制。
- 当 `memory.enabled=True` 且 `register_memory_read=True` 时自动注册。
- handler 通过闭包注入 `MemoryManager`。

### 3.3 `Agent.__init__`

- 新增可选参数 `memory_manager`。
- 默认创建逻辑：
  - `config.agent.memory.enabled == True` 时创建。
  - `StructuredMemoryStore(root_dir=Path(memory_config.memory_root))`。
  - `RuleMemoryExtractor()`。
  - 不默认创建 LLM 提取器。
- 注册 `memory_read` 工具（条件同配置）。

### 3.4 `Agent.run()`

- 启动阶段：
  ```python
  self._memory_context = ""
  if self.memory_manager is not None:
      self._memory_context = self.memory_manager.inject(user_input)
  ```
- 主循环包入 `try/finally`。
- `finally` 中调用 `memory_manager.record()`，并生成 `memory_recorded` Trace 事件。
- 所有终止路径（finish / fatal / max_turns）都会触发记录。

### 3.5 `Agent._build_openai_messages()`

- planner 进度之后追加 `_memory_context`。

### 3.6 提取器增强

- `RuleMemoryExtractor` 除从 `command/code` 解析 `pip install` 外，新增从 stdout 中 `"Successfully installed ..."` 解析包名的兜底逻辑。

## 6. 同行评审修正

| 评审意见 | 处理方式 |
|---|---|
| `memory_read` 结果可能被 ToolResultExternalizer 二次外迁 | `tool_result_externalizer.py` 中把 `memory_read` 与 `context_read` 一起跳过；新增集成测试验证 |
| `_resolve_uri` 使用 Enum 内部 API `_value2member_map_` | 改为 `try/except MemoryCategory(value)` |
| `_build_openai_messages` 使用 `getattr` 防御未初始化属性 | 在 `Agent.__init__` 中初始化 `self._memory_context = ""` |
| 缺少 fatal/max_turns 路径记录测试 | 新增 `test_memory_records_on_fatal` / `test_memory_records_on_max_turns` |
| 缺少 `register_memory_read=False` 测试 | 新增 `test_memory_read_not_registered_when_disabled` |
| pip 包名解析覆盖范围未注释 | 在 `_extract_pip_packages` docstring 中明确覆盖范围与限制 |

## 7. 已知限制与风险

| 风险 | 说明 | 缓解措施 |
|---|---|---|
| `memory_read` 结果过大 | 返回完整 JSON | 通常记忆 content 不大；注入片段仍受 `inject_max_tokens` 限制；外迁器已跳过 `memory_read` |
| 记录失败影响主循环 | `MemoryManager.record()` 吞异常 | `finally` 中调用，失败不阻塞 |
| 注入失败影响主循环 | `MemoryManager.inject()` 吞异常 | 返回空字符串 |
| 数量淘汰竞争 | 多进程同时写可能超限 | MVP 单进程；未来加锁或 SQLite |
| `RuleMemoryExtractor` 解析不完美 | 复杂 shell/stdout 可能漏识别 | 覆盖 MVP 场景 |
