# 自检报告：Task 8.2 — MemoryExtractor + MemoryManager

## 1. 任务目标

在 Task 8.1 存储层基础上，实现 Phase 8 长期记忆的提取层与管理层：

- `MemoryExtractor` 抽象接口
- `RuleMemoryExtractor` 默认规则提取器（不调用 LLM）
- `MemoryInjector` 格式化检索结果为 system prompt 片段
- `MemoryManager` 编排注入、记录、敏感过滤、数量淘汰、清理
- 覆盖上述功能的单元测试

## 3. 实现要点

### 3.1 `MemoryExtractor`

- 抽象方法 `extract(trace, state, run_metadata) -> list[MemoryEntry]`。
- 提取器内部调用 `trace.to_dict()`，与 Trace 实现解耦。

### 3.2 `RuleMemoryExtractor`

覆盖三类 MVP 记忆：

- **environment**：`tool_execution` 中 `sandbox_exec` 成功执行 `pip install`，解析包名（过滤 `--options` 和版本限定符）。
- **artifacts**：
  - 从 `tool_execution` 的 `command` 与 `content` 中识别 `/workspace/`、`/tmp/` 等绝对路径，以及带扩展名的通用绝对路径。
  - 从 `AgentState.artifacts` 中读取显式记录的产物。
- **failure_patterns**：同一 step 内成对的 `error_classification` + `reflection` 事件，抽取 `exc_type`、`tool_name`、`signature`、恢复策略、`signature_detail`。

未实现：

- `task_summaries` / `preferences` 的 LLM 提取（Task 8.4 或可选增强）。
- `tool_result_externalized` 直接转产物（避免把 context cache URI 误判为文件产物）。

### 3.3 `MemoryInjector`

- 把 `MemoryEntry` 列表格式化为 `[历史记忆]` 文本块。
- 受 `inject_max_entries` 与 `inject_max_tokens` 限制。
- 按 1 token ≈ 3 字符做保守字符预算，避免引入 tiktoken 循环依赖。

### 3.4 `MemoryManager`

- `inject(user_input)`：未启用或空输入返回空字符串；失败被吞。
- `record(trace, state, run_metadata)`：
  - 调用规则提取器。
  - 可选 LLM 提取器失败不影响规则提取结果。
  - 敏感信息过滤（content/summary/tags）。
  - 按 `max_entries_per_category` 淘汰最旧条目后写入 store。
  - 失败返回空列表。
- `cleanup()`：安全委托给 store；当前配置无 `max_age`，故返回 0。

### 3.5 敏感过滤

- `MemoryConfig.sensitive_patterns` 作为子串黑名单。
- 对 `content` 递归扫描：key 命中黑名单则 value 置为 `[REDACTED]`；字符串 value 命中则替换。
- 对 `summary` 和 `tags` 同样做字符串级替换。

## 6. 已知限制与风险

| 风险 | 说明 | 缓解措施 |
|---|---|---|
| 路径识别误报 | 正则可能匹配非产物路径 | 仅识别 workspace/tmp 前缀或带扩展名的绝对路径 |
| pip 包名解析不完美 | 复杂 shell 命令（管道、变量）可能误解析 | MVP 场景为简单 `pip install pkg` |
| 注入 token 估算粗略 | 1 token ≈ 3 字符是经验值 | 设置保守，实际占用只会更少 |
| failure_pattern `resolved` 不准确 | 未跟踪后续是否成功恢复 | MVP 标记为 `False`，8.4 可引入反馈/审计修正 |
| 数量淘汰在 store 层之上 | 存在并发窗口 | 单进程/测试场景足够；高并发未来加锁 |
