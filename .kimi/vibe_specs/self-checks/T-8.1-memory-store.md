## 3. 实现要点

### 3.1 `MemoryCategory`

- 使用 `(str, Enum)` 风格，与项目现有 `StepStatus` 保持一致。
- 五个类别：`environment`、`artifacts`、`failure_patterns`、`task_summaries`、`preferences`。

### 3.2 `MemoryEntry`

- dataclass 定义，包含 `entry_id`、`category`、`content`、`summary`、`tags`、`uri`、`created_at`、`updated_at`、`confidence` 等字段。
- `uri` 为空时自动按 `hermes://memory/<category>/<entry_id>.jsonl` 生成。
- `confidence` 默认 1.0，为未来 LLM 提取器预留置信度机制。

### 3.3 `MemoryQuery`

- 支持按 `categories`、`tags`、`text`、`top_k`、`time_range` 检索。
- `categories` 使用 `MemoryCategory` 枚举，类型安全。

### 3.4 `MemoryStore`

- 抽象接口包含 `save`（返回 `MemoryEntry`）、`get`、`query`、`delete`、`cleanup`、`list_entries`。
- `save` 为 upsert 语义，`get` 按 `entry_id` 读取，`delete` 删除文件。

### 3.5 `StructuredMemoryStore`

- 文件目录结构：`.hermes/memory/<category>/<entry_id>.jsonl`。
- 每条记忆一个文件，单行 JSON，便于人工审计。
- `query` 实现两阶段策略：
  1. 按 category、tags、time_range 过滤。
  2. 按 text 与 `summary`/`tags`/`content` 做 token/字符重叠打分，返回 top_k。
- 检索打分同时支持英文单词和中文单字，通过简单正则分词实现。
- `entry_id` 严格校验 `^[a-zA-Z0-9_-]+$`，防止路径遍历。
- 对人工编辑导致缺少时区的 datetime，按 UTC 防御性处理。

### 3.6 `MemoryConfig`

- 默认 `enabled=False`，与 `ContextCompressionConfig` 策略一致。
- 包含存储根目录、检索数量、注入长度限制、敏感过滤、LLM 提取开关等字段。
- 接入 `AgentRuntimeConfig`，支持 YAML 加载。

## 4. 同行评审与修正

评审结论：**有条件通过**。

主要意见及处理：

| 评审意见 | 处理方式 |
|---|---|
| `MemoryStore.save` 返回类型与 spec 不一致 | 更新 spec，明确 `save` 返回 `MemoryEntry` |
| `get()` 未在 spec 中声明 | 更新 spec，将 `get()` 加入抽象接口 |
| `list_entries` 参数类型 spec 为 `str` | 更新 spec 为 `MemoryCategory \| None` |
| 缺少 `time_range` 测试 | 新增 `test_structured_store_query_by_time_range` |
| 缺少组合过滤测试 | 新增 `test_structured_store_query_combined_filters` |
| 缺少空 store / cleanup(None) 测试 | 新增对应边界测试 |
| `get`/`delete` 路径遍历未覆盖 | 新增 `test_structured_store_get_rejects_path_traversal`、`test_structured_store_delete_rejects_path_traversal` |
| `query.text` 纯空白时过滤掉所有结果 | 修复：先 `.strip()`，空白视为无过滤条件 |
| `categories=[]` / `tags=[]` 被视为不过滤 | 修复：显式判断 `is not None`，空列表表示无匹配 |
| 手动编辑 JSONL 可能导致 naive datetime | 修复：`_parse_datetime` 缺少时区时假设为 UTC |
| 未验证默认时间戳带时区 | 新增 `test_memory_entry_default_timestamps_are_utc_aware` |
| `MemoryQuery` 空列表语义未在 docstring/测试明确 | 补充 docstring + `test_structured_store_query_empty_list_means_no_filter` |
| 加载 JSONL 时未校验 `entry_id` | `_entry_from_json` 增加 `_validate_entry_id` 校验 |
| `save()` 覆盖旧记录不更新 `updated_at` | 修复：覆盖时重置 `entry.updated_at = datetime.now(timezone.utc)` |
| `time_range` 传入 naive datetime 会异常 | `_filter_time_range` 中对范围端点调用 `_ensure_aware_dt()` |
| 数字/布尔值 content 无法被检索 | `_flatten_values()` 将非字符串值转为字符串纳入索引 |

## 7. 已知限制与风险

| 风险 | 说明 | 缓解措施 |
|---|---|---|
| 检索算法简单 | 仅关键词/字符重叠，无语义匹配 | MVP 数据量小，未来可替换 `MemoryStore.query` 实现 |
| 文件并发写入 | 多进程同时写可能冲突 | 按 entry 独立文件，append-only JSONL 降低冲突；MVP 不考虑高并发 |
| 中文分词粗糙 | 中文按单字匹配 | 足够支撑 MVP 关键词召回 |
| `max_entries_per_category` 未在 Store 层实施 | 数量淘汰由 `MemoryManager` 负责 | 当前 Task 未实现 Manager，数量淘汰在 Task 8.2 落地 |
